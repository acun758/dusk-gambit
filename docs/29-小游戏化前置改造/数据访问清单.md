# 数据访问清单（29 号文档 R2）

生成日期：2026-09-18 · 与代码交叉核对方式：`rg "\.from\(|\.rpc\("` 全仓扫描，命中范围仅 `src/data/**` 与 `src/integrations/supabase/**`（生成客户端）。

**边界结论**：全应用没有第二处数据访问入口。页面与组件一律 `import { ... } from "@/data/db"`，由 `db.ts` 代理到 `src/data/backend/`（provider 由 `src/config/app-config.ts` 的 `BACKEND_PROVIDER` 切换：`default` = 现网，`cloud` = 将来微信云开发骨架）。

## 二、迁移映射（将来换云开发只动这一层）

- 只需实现 `src/data/backend/gateway.cloud.ts` 与 `cloudRealtime` 的同名方法，把 `BACKEND_PROVIDER` 改为 `cloud`；`db.ts` 及以上（页面、hooks、core）零改动。
- 服务端权威逻辑（匹配、落子校验、超时、结算、奖励、晋级）对应 13 个 RPC，需要在云开发侧以云函数一比一重建，函数名与入参保持不变，前端不必改。
- 存储桶名集中在 `STORAGE_CONFIG.avatarBucket`，换成云存储只改配置一处。
