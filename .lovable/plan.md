# 34 号：联网大厅（Arena）

按文档分期执行，本轮做 **M1：大厅列表 + 建房 + 数据模型**，M2 观棋在 M1 发布验收后单独做。玩家可感知的其他部分零变化，不动结算与公平性代码。

## 本轮要做的事

### 1. 新页面「联网大厅」（/arena）
- 三个标签：待加入 / 进行中 / 我的房间。
- 每张房卡：迷你棋盘（用现有棋子与战盘素材，不新增图片）、双方昵称与积分（空位显示「待加入」）、时制一行、准入门槛、状态、相对时间（「11 秒前」）。
- 进行中房卡的迷你棋盘每 2 秒节流刷新；房间列表走实时推送，另有下拉手动刷新兜底。
- 空态给「创建第一间对局场」入口，暗黑观测厅调性（古金高光 + 黑曜底），沿用现有页眉与中英双语规范。
- 底部导航与左侧栏加入「大厅」入口。

### 2. 创建房间弹窗
- 执子：执白 / 执黑 / 猜先（服务端随机，创建后展示结果）。
- 公开或私密：私密不入列表，用房间短码邀请，可一键复制。
- 局时 5/10/15/20/30 分钟 + 自定义；步时 1/2/3 分钟 + 自定义；每步加秒 0/3/5/10。
- 积分限制用段位语言：不限 / 限兵段（≤1400）/ 限马段（≤1600）/ 1700+。
- 创建成功进入等待页：房间信息、短码复制、对手加入实时提醒。

### 3. 服务端（唯一权威）
- 新表 `rooms`：房主、客人、状态（待加入/进行中/已结束）、公开性、短码、执子选择、局时、加秒、步时、积分上下限、创建与关闭时间；开启行级保护，公开房任何人可读，写入只走服务端。
- 建房、加入、取消、列表、我的房间共五个服务端接口；加入时原子校验：房间仍空、积分达标、不是自己，先到先得，后到者收到「房间已满」。积分门槛在服务端判定，改前端请求无法绕过。
- 开局时由房间派生一局对弈（复用现有对局与结算链路），房间转为进行中；对局结束后房间关闭。
- 待加入超过 10 分钟无人加入自动解散。

### 4. 数据访问层
- 所有新接口经 `src/data/db.ts` 与 `src/data/backend/` 网关暴露，页面不直接触碰云 SDK，命名保持领域名词。

## 不在本轮范围
- 观棋（M2）、实时胜率浮标、预置表情。
- 任何自由文本聊天、私信、好友系统；房间短码输入是唯一文本入口。

## 技术说明
- 实时订阅按 30 号教训独立开通道，不与对局帧、档案共用一条。
- 迷你棋盘复用现有棋子资产渲染，新增页面资源增量控制在 200KB 内。
- 验收：双账号建房→可见→加入→对弈结算全链；伪造请求加入高门槛房被拒；超时解散与并发加入冲突行为正确；四档视口无溢出、零报错。
