# 31 号新款阔折叠屏适配

## 目标
在不改变电脑端、现有 iPad/iPhone 表现，不触碰玩法、实时同步、结算与公平性代码的前提下，让新款阔折叠外屏及展开态复用现有手机档和平板档，并支持对局中动态折叠/展开。

## 实施顺序

### R1：把平板结构档下沿扩展至 600px
- 在全局样式中新增 `tab: 600px` 断点。
- 逐一审查九条页面及共享页眉、底栏、棋盘区域，只把会改变单双栏、显示隐藏、横纵排列的 `md:` 结构规则迁到 `tab:`。
- 字号、间距、圆角等纯视觉 `md:` 规则继续保持 768px，避免改变现有 iPhone/iPad 和电脑端观感。
- 将 600–767px 的棋盘、复盘区、残局关卡区等现有平板结构补齐；1024px 以上布局保持原样。

### R2：按朝向选择已有背景
- 横握且宽度至少 600px 使用 desktop 背景；竖握且宽度至少 600px 使用 iPad 背景；宽度不足 600px 使用 iPhone 背景。
- 仅使用 `<picture>` / CSS media query，不增加 JavaScript 尺寸监听，不新增或删除背景资产。
- 同步入口预热逻辑，只预热当前朝向对应的资源；背景继续居中裁切。

### R3：加固短视口
- 将玩家页面中仍使用的 `100vh` / `min-h-screen` 统一为动态视口高度语义，避免折叠展开后高度残留。
- 针对 920×640 的对弈棋盘、双时钟与信息区，及 480×700 的底部导航和浮动操作区做紧凑适配，确保内容可达且不形成内滚动陷阱。
- 仅增加 600–1023px 与短高度条件下的约束，不改既有桌面档。

### R4：动态切换不丢状态
- 在同一浏览器页面内从 474×696 切换至 920×640，不重载页面。
- 开始一局 AI 对弈并落子后再切换，核对棋局、着法、时钟和战报相关状态保留，页面即时重排。

- 每档检查 9 条路由：`/`、`/battle`、`/crucible`、`/analysis`、`/dynasty`、`/puzzles`、`/arsenal`、`/archive`、`/hall-of-fame`。
- 每个组合保存截图，共 36 张；检查横向溢出、固定栏遮挡、文本/控件重叠和页面错误。
- 额外完成一次对局中的 474×696 → 920×640 动态切换测试。
- 交付逐条 R1–R4 自测报告、截图组、改动摘要，并明确声明未触及结算/公平性代码。
