# 为小游戏移植做"换皮级"重构（已按军师四条约束修订）

军师的四条约束全部合理，我完全按他的写法执行。引擎包已经接进来了：`src/core/engine/`（engine / worker / engineClient + 单例入口），15 项回归测试全部通过（开局 b1c3 cp=28、depth 5 约 458ms、易位/过路兵/升变/禁易位全对）。

## 已完成

- 引擎落位 `src/core/engine/`，测试脚本在 `test/engine.test.ts`，可随时复跑。
- 暂走主线程降级路径（单次 ≤600ms，实测远低于预算）；独立 worker 分包后只换一个参数，上层零改动。

## 第一步：逻辑与画面分离（按军师规则）

- `core/rules.ts`：**只做 chess.js 的薄封装**，不自研规则，前端与服务端校验共用同一套；引擎只"想"不"判"。
- `core/clock.ts`、`core/settle.ts`：**只做显示计算**，代码注释里写死"权威判负与结算在服务端，前端结果仅为预显示"。
- `core/review.ts`：按军师公式实现——每手两轮搜索取差值，loss ≤30 最佳 / ≤90 良好 / ≤200 一般 / ≤400 失误 / >400 大漏着；ACPL 取全局平均；准确率用 Lichess 公式换算。
- `core/score.ts`：心智评分从残局页抽出来，纯计算。
- 对弈页的陪练 AI 也换成同一引擎（三档强度对应 skill 4 / 12 / 20），替换现有的简易搜索。

## 第二步：数据访问收敛

- `src/lib/db.ts`：只管数据读写，接口用领域名词（`fetchProfile` / `submitMove` / `settleMatch` / `fetchLadder`…），**全文不出现云服务商名字**。
- `src/lib/realtime.ts`：实时订阅单独放，协议沿用 `duel-protocol.ts`。
- 现有 10 处直连改为调用这两个模块；换微信云开发时只替换实现。

## 第三步：字体（按军师方案，不做取舍）

- 4 套砍到 2 套：Cinzel 做标题、思源黑/宋做正文，Fira Sans 用系统字体栈顶替。
- UI 文案用 3500 常用字子集自托管；玩家昵称等用户内容一律走系统字体渲染——零牺牲、体积最小。
- 去掉 Google Fonts 外链。

## 第四步：图片外链本地化

按页面分批，先入口页与首页，其余后续；便于小游戏分包。

## 不会改动

页面视觉（污渍纸质感）、导航结构、玩法手感、数据库表与现有服务端函数。
